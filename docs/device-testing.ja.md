# 実機のSesameで検証する

[English](device-testing.md)

このプロジェクトは全体がテストで覆われていますが、**まだ一度も実機の錠前に対して動かしていません。** これは最初の一巡のための手順です。想定と違う挙動を「回避してしまう」のではなく「気づく」ように書いてあります。

各手順は、やること・期待される結果・違った場合の意味、の順に並べています。期待される文言は、コードが実際に出力する文字列をそのまま引用しています。

## まだ検証できていないこと

3点は、公開されているソースと仕様からの**推論**であって、観測結果ではありません。この手順が失敗するとしたら、まずここです。

| 手順 | 推論の内容                                                                            | 読んだ出典                                   |
| ---- | ------------------------------------------------------------------------------------- | -------------------------------------------- |
| 4    | 拡張が`data:` URLのプロジェクトを読み込むと「サンドボックスなしで実行」の選択肢が出る | `scratch-gui`の`canLoadExtensionFromProject` |
| 5    | service `0xFD81`で絞ったデバイス選択画面にSesameが出る                                | CANDY HOUSEのadvertisingドキュメント         |
| 7    | 錠前が動いたとき`mech_status`が自発的にpushされる                                     | CANDY HOUSEの`81_mechstatus`ドキュメント     |

## 始める前に

- **ChromeまたはEdge**、desktopかAndroid。Safari、Firefox、iOSにはWeb Bluetoothが無く、この手順はどれも実行できません
- **セサミアプリ**にサインイン済みで、錠前が登録されていること
- 共有する**オーナー鍵またはマネージャー鍵**。ゲスト鍵では動きません。secretの半分をサーバーが保持しているためです
- Bluetoothがオンで、錠前から数メートル以内にいること
- **締め出されることが起こり得ない場所で行ってください。** ドアを開けた状態にするか、手に持てる錠前で試してください。手順8は物理的に錠前を動かします。このbuildは遠隔操作が有効です
- 手順5の前にセサミアプリを閉じてください。スマートフォンが接続を掴んでいる錠前は、ブラウザの選択画面に出ないことがあります

## 1. keyholderを開く

<https://kubohiroya.github.io/turbowarp-sesame/keyholder/> を開きます。

**期待:** 見出し `Sesame keyholder` と、ステータス行の `Ready.`

macOS、Android、ChromeOSでは **Scan QR code with camera** ボタンが表示されます。WindowsとLinuxでは非表示になり、代わりに「コードのテキストを貼り付けてください」という注記が出ます。これらのChromeにはプラットフォーム側のバーコード対応が無いためです。

**ステータス行にエラーが出る場合**、ページがストレージへ到達できていません。プライベートウィンドウやサイトデータの遮断が原因です。通常ウィンドウで開いてください。

> このアドレスは検証用です。`kubohiroya.github.io`上の他のあらゆるページとoriginを共有し、`frame-ancestors`を送れないためどのサイトからでも埋め込まれます。**大切な鍵をここに置いたままにしないでください** — [keyholderのホスティング](keyholder-hosting.ja.md)を参照。

## 2. 鍵をペアリングする

セサミアプリで**オーナー鍵またはマネージャー鍵**をシェアし、QRコードを表示します。

keyholderでデバイス別名を入力します。サンプルプロジェクトが期待している `front-door` を使ってください。続いて **Scan QR code with camera** を押し、カメラを許可します。スマートフォンの画面を10〜20cmの距離に、輝度を上げ、映り込みを避けて傾けてかざします。

**期待:** パスキーの確認（Touch ID、Windows Hello）が出たのち、ステータス行が `Paired "front-door" (<錠前のUUID>).` になり、**Paired Sesames** に現れること。

**`This is a guest key, which does not contain the half of the secret that Bluetooth needs. Share an owner or manager key instead.` と出た場合** — ゲスト鍵をシェアしています。マネージャー鍵をシェアしてください。

**`This is not a sesame sharing QR code.` と出た場合** — アプリが別種のコードを表示しています。任意のQRリーダーでそのコードを読み、テキストが `ssm://UI?t=sk` で始まるか確認してください。

**`This sesame QR code is in a format this project does not know` と出た場合** — 種類は合っていますが、中身がこのパーサの理解するレコードではありません。メッセージの末尾にペイロードの長さと先頭4バイトが付きます。これは形式を特定するための情報で、**報告しても安全**です（コード本体は安全ではありません）。新しいアプリ版は、公開SDKに符号化が無い短命の暗号化共有コードを表示することがあります。下の手入力を使ってください。

### QRコードが読めない場合

ページ下部の **…or enter the key by hand** まで進み、錠前のUUIDと32文字のsecret keyを入力してください。**これはこのプロジェクトのDirect modeが必要とするのと同じ2つの値**なので、すでにDirect modeを使っているなら手元にあるはずです。

secret keyは錠前を開けられます。チャットやissue、このページ以外のどこへも貼り付けないでください。

**パスキーの確認が出ない場合**、チェックボックスがパスフレーズへフォールバックしています。それで構いません。入力して覚えておいてください。

**続いてページをリロードしてください。** デバイスが一覧に残っている必要があります。残っていなければ何も保存されておらず、以降の手順は動きません。

## 3. Service Workerを確認する

keyholderのまま、DevToolsの **Application** を開きます。

**期待:** **Service Workers** にworkerが1つ、_activated and running_。**Cache Storage** に `sesame-keyholder-<digest>` という名前のキャッシュがあり、2件入っていること。

続いてNetworkパネルで **Offline** にチェックしてリロードします。**期待:** ページが読み込まれること。確認後、Offlineを外してください。

**workerが無い場合**もページは動きます。毎回ネットワークが必要になるだけです。

## 4. プロジェクトを読み込む

<https://kubohiroya.github.io/turbowarp-sesame/turbowarp-sesame-app.sb3> をダウンロードします。

<https://turbowarp.org> を開き、ファイルをページへドラッグします。

**期待:** カスタム機能拡張を読み込むか尋ねるダイアログが出て、**「サンドボックスなしで実行する」チェックボックスが含まれていること。** チェックを入れて許可します。

**ここが最も確認したい推論です。** そのようなチェックボックスが出ない場合、そこで止めて**ダイアログの文言をそのまま記録してください。** これが無ければ機能拡張はsandbox内で動き、Web Bluetoothが使えず、手順5は成功し得ません。

**読み込み後の期待:** ステージに説明の背景が表示され、Sesameのブロックがパレットに現れること。

## 5. 接続する

緑の旗をクリックします。**期待:** `Press SPACE to connect over Bluetooth.`

**SPACE**を押します。

**期待:** ブラウザのBluetoothデバイス選択画面が開き、お使いのSesameが一覧に出ること。

**何も起きない場合**、`last Sesame error` ブロックをパレット領域へドラッグしてクリックしてください。どの段階で失敗したかが分かります。

| メッセージ                                                                                              | 意味                          |
| ------------------------------------------------------------------------------------------------------- | ----------------------------- |
| `Bluetooth mode requires reloading this custom extension with "Run extension without sandbox" enabled.` | 手順4のチェックが入っていない |
| `This browser has no Web Bluetooth…`                                                                    | ブラウザが違う                |
| `Keyholder URL must use HTTPS.`                                                                         | プロジェクトが編集されている  |

**選択画面は開くが何も出ない場合**、錠前が範囲外か、スマートフォンが接続を掴んでいます。セサミアプリを閉じて再試行してください。

デバイスを選びます。

**数秒以内の期待:** `Connected. L locks, U unlocks.`

**代わりにエラーが出た場合**、それは `last Sesame error` の内容で、どの段階かを示します。

| メッセージ                                                       | 意味                                           |
| ---------------------------------------------------------------- | ---------------------------------------------- |
| `The Sesame did not start a session. Move closer and try again.` | 接続はしたがrandom codeが届かない              |
| `The Sesame refused to log in to the Sesame (result 9).`         | ペアリング済みのsecretがこの錠前のものではない |
| `The key could not be unlocked…`                                 | keyholderのパスキーかパスフレーズが違う        |
| `The keyholder did not load.`                                    | iframeを取得できなかった                       |

## 6. 状態を読む

`Sesame status [CHSesame2Status]` ブロックをクリックします。

**期待:** `locked` または `unlocked` が、錠前の実際の位置と一致すること。

`batteryPercentage` と `batteryVoltage` も試し、セサミアプリの表示と比べてください。ここでは生の測定値から計算しているので、**大きく食い違えば換算式が誤っています。**

`wm2State` は空を返します。これは正しい挙動です。WiFiモジュールの状態であり、Bluetoothセッションには存在しないためです。

## 7. 動きを検知する

錠前を**手で**動かします。サムターンでも、スマートフォンのアプリからでも構いません。

**期待:** こちらが何も操作しなくても、1秒ほどで新しい状態がプロジェクトに表示されること。錠前自身のpushによって `when the Sesame state changes` ハットが動いています。

**何も起きない場合**、この機種は状態を自発的にpushしないのかもしれません。記録してください。状態ブロックは引き続き動きますが、ハットブロックは動きません。

## 8. 錠前を操作する

**ドアを開けた状態で。**

**U**を押します。**期待:** 錠前が物理的に解錠されること。
**L**を押します。**期待:** 錠前が物理的に施錠されること。

それぞれの後に `Sesame status [CHSesame2Status]` を読み、錠前が実際に行った動作と一致することを確認してください。

## 報告してほしいこと

想定と違った場合、原因の特定に効くのは次の情報です。

- `last Sesame error` の正確な文言
- 手順4については、ダイアログの正確な文言と、**サンドボックスのチェックボックスがそもそも出たかどうか**
- 手順2でQRが拒否された場合、そのコードのテキストが何で始まっているか
- ブラウザとバージョン、OS、錠前の機種
- どちらのページでも、DevToolsのコンソールに出ているもの

## 検証のあとに

`kubohiroya.github.io` のkeyholderには、ペアリングした鍵がまだ残っています。そこで **Forget** するか、keyholderを専用のoriginへ移してペアリングし直してください。[keyholderのホスティング](keyholder-hosting.ja.md)がその手順です。
